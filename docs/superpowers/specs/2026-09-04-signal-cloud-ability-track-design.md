# Signal Cloud Ability Track

## 结论

将现有能力词云改造成桌面端“能力轨道”：词云保留全部现有关键词和权重，四个能力方向成为可选择的交互入口，选择结果同步影响词云、项目和工作流关联信息。移动端不做结构性改造。

## 目标

- 让用户在 2 秒内理解这一区域展示的是 Leila 的技术能力如何服务真实交付。
- 让词云具有明确的 hover、selected、reset 反馈，不再像静态图片。
- 减少左侧词云与右侧技能列表的重复。
- 将区域高度收紧到桌面端约 320–380px 的阅读尺度。
- 保留现有 57 个关键词、权重、四个技能分类、外链和原有文案。

## 桌面构图

桌面端使用单一能力场：上方是较克制的标题和一句说明，中部是词云能力场，下方或侧边是四个能力方向入口及当前方向的解释。词云占主要视觉区域，但不再占据整块高矩形空间。整体沿用当前浅色背景、珊瑚橙主强调色、橄榄绿辅助色和编辑式不对称布局。

能力方向：

1. 前端：界面、组件、路由和交互。
2. 后端：接口、数据、服务连接。
3. 工程化：微前端、构建、环境和发布链路。
4. AI 与研究：Agent、RAG、LLM、提示词和工作流界面。

## 交互状态

- 初始状态：全部关键词可读，核心词有自然的字号层级。
- Hover：当前词提高对比度并轻微放大，邻近词保持稳定，避免持续漂移影响阅读。
- 分类选中：相关关键词提高对比度，非相关关键词降低透明度；当前分类标题变色；关联项目和工作流节点出现选中状态。
- 再次点击当前分类：恢复全部关键词和项目状态。
- Resize：使用 ResizeObserver 按实际容器尺寸重算布局，避免固定高度造成裁切和变形。

## 数据关系

现有 `signalCloudKeywords` 数据继续作为唯一词云数据源。通过现有技能组和项目内容建立分类映射，不新增虚构技术名词。分类摘要负责解释“这些能力用于什么工作”，完整技术链接仍然保留在可访问的索引区域。

## 不做的事情

- 不删除关键词、技能链接、项目内容或原有文案。
- 不把词云改成普通标签列表。
- 不使用持续旋转、无意义漂浮或大面积发光动画。
- 不增加黑色背景、左侧竖线、下划线或卡片阵列。
- 不新增移动端结构性布局调整。

## 验收标准

- 桌面端词云高度明显低于当前版本，右侧或下方不出现大面积空白。
- 点击四个能力方向时，词云、分类说明和关联项目均有可见反馈。
- 鼠标 hover 词语时有明确状态变化。
- 长词不会被裁切，窗口调整后布局稳定。
- 现有关键词总数、技能分类和链接数据仍然存在。
- `npm test`、`npm run build` 和 `git diff --check` 通过。
