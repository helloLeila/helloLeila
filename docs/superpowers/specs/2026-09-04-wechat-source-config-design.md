# 公众号来源配置设计

日期：2026-09-04  
状态：已获用户确认，待实现

## 目标

在 `/events/` 活动雷达页面增加“来源配置”按钮，用右侧抽屉管理 37 个公众号来源。用户只填写或修改公众号名称，不填写公众号 ID、文章 URL、RSS 地址或登录信息。

本次采用：

- 布局：右侧抽屉，活动列表保持可见
- 保存范围：当前浏览器本地保存
- 搜索入口：公众号名称驱动公开搜索词
- 原始来源：37 个既有来源全部保留，不提供删除原始来源的操作

## 非目标与边界

GitHub Pages 是静态站点，浏览器中的本地配置不能直接写回 GitHub 仓库，也不能直接修改 GitHub Actions 的每日任务。因此本次配置只保存到当前浏览器，用于维护名称和生成搜索词预览。

本次不在浏览器端执行跨域抓取、不读取微信登录态、不保存 Cookie、不自动确认同名公众号，也不把本地修改假装成已经同步到公开数据。

如果将来要让每日 Actions 使用新的名称，需要另行增加导出、提交或服务端同步流程。本设计不包含该流程。

## 用户流程

1. 用户进入 `/events/`，点击页头的“来源配置”按钮。
2. 页面打开右侧抽屉，展示 37 个来源及其当前发现状态。
3. 用户可以在顶部输入框新增一个公众号名称，也可以修改既有名称。
4. 用户可以按名称搜索抽屉内的来源。
5. 每个来源显示名称、状态和自动生成的搜索词预览：

   ```text
   "公众号名称" 微信公众号 活动
   ```

6. 用户点击“保存到本机”，配置写入浏览器 `localStorage`，并显示本地保存时间。
7. 用户点击“恢复默认”，撤销本机修改，恢复仓库内的 37 个初始名称。
8. 用户点击遮罩、关闭按钮或按 `Esc` 关闭抽屉；焦点返回“来源配置”按钮。

原始 37 个来源不显示删除按钮。用户新增的自定义来源可以通过“恢复默认”清除；恢复操作只影响本机配置。

## 界面结构

### 页头入口

在活动雷达页头的更新时间区域旁增加一个带齿轮图标的按钮：

```text
⚙ 来源配置
```

按钮使用 `aria-haspopup="dialog"`，打开后将焦点移动到抽屉标题或名称搜索框。

### 右侧抽屉

抽屉包含：

- 标题“来源配置”
- 37 个来源总数
- 已确认、待确认、不可用数量
- 名称搜索框
- 新增公众号名称输入框和“添加名称”按钮
- 来源列表
- “保存到本机”按钮
- “恢复默认”按钮
- 本地保存状态提示

每个来源行包含：

- 可编辑的公众号名称
- 当前状态（只读，来自公开数据 JSON）
- 搜索词预览（只读）
- 原始来源标识或自定义来源标识

不提供地址输入框，不提供微信 ID 输入框，不提供登录入口。

### 响应式行为

- 桌面端使用固定宽度右侧抽屉，宽度约 420px。
- 窄屏端抽屉变为全屏面板，内容可以纵向滚动。
- 抽屉打开时禁止页面背景滚动。
- 支持键盘 `Tab`、`Shift+Tab`、`Esc` 和可见焦点状态。

## 数据模型与持久化

新增 `src/events/sourceConfig.js`，负责默认目录、本地配置读写和名称规范化。默认目录从 `data/wechat-event-sources.json` 复用，避免在前端重复维护 37 个名称。

建议的本地存储键：

```text
helloLeila.events.source-config.v1
```

存储结构：

```json
{
  "version": 1,
  "updatedAt": "2026-09-04T10:00:00+08:00",
  "sources": [
    {"id": "qbitai", "name": "量子位", "custom": false},
    {"id": "custom-...", "name": "自定义公众号", "custom": true}
  ]
}
```

读取顺序：

1. 从静态来源目录读取 37 个默认来源。
2. 读取本机存储；如果 JSON 损坏、版本不支持或名称为空，则忽略损坏项并回到默认值。
3. 以来源 ID 合并公开数据中的状态，不让本机名称修改伪造来源状态。
4. 自定义来源使用稳定的本地 ID，直到用户恢复默认。

名称规范化规则：去除首尾空白、合并连续空格、拒绝空名称，保留中英文、数字和原始标点。重复名称不重复添加；重复时聚焦已有行并提示用户。

## 组件边界

### `SourceConfigDrawer.jsx`

负责抽屉展示、打开关闭、键盘交互、名称编辑、新增和保存按钮。它不负责活动数据抓取。

### `sourceConfig.js`

负责：

- 读取默认来源目录
- 规范化名称
- 生成搜索词预览
- 读取和写入 `localStorage`
- 恢复默认配置
- 合并公开来源状态

### `EventsApp.jsx`

负责：

- 渲染页头入口
- 控制抽屉开关
- 将 `payload.sources` 状态传给抽屉
- 保持现有活动筛选和活动列表逻辑不变

### `events.css`

增加抽屉、遮罩、来源行、状态标记、滚动区域和移动端布局样式，继续使用现有活动雷达的颜色和字体变量。

## 数据流

```text
data/wechat-event-sources.json
          ↓
  默认来源目录（37 条）
          ↓ 与 payload.sources 合并状态
   SourceConfigDrawer
          ↓ 用户编辑名称
       localStorage
          ↓
   页面刷新后恢复本地配置
```

本地配置只影响配置面板和本地名称视图。当前公开活动列表仍然读取 `wechat-events.json`，不会因为用户在浏览器里改名而伪造新的活动数据。

## 错误处理

- `localStorage` 不可用时，页面继续使用默认来源，并显示“本机存储不可用”。
- 本地 JSON 解析失败时，丢弃本地副本并恢复默认值。
- 名称为空时不允许保存，并在输入框附近显示明确提示。
- 同名新增不创建重复项。
- 公开活动数据请求失败时，抽屉仍然显示 37 个默认名称；来源状态显示“状态暂不可用”。
- 保存按钮在保存完成前禁用，完成后显示保存时间。

## 后续可扩展项

如果用户之后需要让配置真正驱动每日搜索，需要单独设计以下之一：

- 导出 JSON 后手动提交到仓库
- GitHub OAuth/服务端 API 写回仓库
- 独立后端保存来源配置并供 Actions 读取

这些方案会改变权限、部署和安全边界，不在本次本地配置功能中混入。
