# 公众号来源配置设计

日期：2026-09-04  
状态：已获用户确认，待实现

## 目标

在 `/events/` 活动雷达页面增加“来源配置”按钮，用右侧抽屉管理 37 个公众号来源。用户只填写或修改公众号名称，不填写公众号 ID、文章 URL、RSS 地址或登录信息。

本次采用：

- 布局：右侧抽屉，活动列表保持可见
- 保存范围：本地开发页写回项目 JSON
- 搜索入口：公众号名称驱动公开搜索词
- 原始来源：37 个既有来源全部保留，不提供删除原始来源的操作

## 非目标与边界

GitHub Pages 是静态站点，部署后的公开页面不能直接写回 GitHub 仓库。本次采用本地开发页配置：Vite 开发服务器提供仅本机可用的配置 API，接收名称列表并写回项目中的 `data/wechat-event-sources.json`。用户随后提交并推送这个 JSON，GitHub Actions 才会使用新名称。

本次不在浏览器端执行跨域抓取、不读取微信登录态、不保存 Cookie、不自动确认同名公众号，也不把未提交的本地修改假装成已经同步到 GitHub 或公开数据。

配置保存后仍需要用户执行 Git 提交和推送；本次不自动执行 Git 提交、不自动推送远程仓库，也不在公开页面暴露写入接口。

## 用户流程

1. 用户进入 `/events/`，点击页头的“来源配置”按钮。
2. 页面打开右侧抽屉，展示 37 个来源及其当前发现状态。
3. 用户可以在顶部输入框新增一个公众号名称，也可以修改既有名称。
4. 用户可以按名称搜索抽屉内的来源。
5. 每个来源显示名称、状态和自动生成的搜索词预览：

   ```text
   "公众号名称" 微信公众号 活动
   ```

6. 用户点击“保存到项目 JSON”，页面向本地 Vite 配置 API 发送名称列表。
7. 本地 API 校验数据并原子写入 `data/wechat-event-sources.json`，页面显示“已保存到项目 JSON”和保存时间。
8. 用户点击“恢复默认”，撤销未保存的页面编辑，恢复当前项目 JSON 中的 37 个名称。
9. 用户点击遮罩、关闭按钮或按 `Esc` 关闭抽屉；焦点返回“来源配置”按钮。

原始 37 个来源不显示删除按钮。用户新增的自定义来源可以通过“恢复默认”清除；恢复操作只撤销当前页面尚未保存的编辑。

## 界面结构

### 页头入口

在活动雷达页头的更新时间区域旁增加一个带齿轮图标的按钮：

```text
⚙ 来源配置
```

按钮使用 `aria-haspopup="dialog"`，打开后将焦点移动到抽屉标题或名称搜索框。

### 右侧抽屉

抽屉包含：

- 标题“来源配置”
- 37 个来源总数
- 已确认、待确认、不可用数量
- 名称搜索框
- 新增公众号名称输入框和“添加名称”按钮
- 来源列表
- “保存到项目 JSON”按钮
- “恢复默认”按钮
- 本地 API 和项目 JSON 保存状态提示

每个来源行包含：

- 可编辑的公众号名称
- 当前状态（只读，来自公开数据 JSON）
- 搜索词预览（只读）
- 原始来源标识或自定义来源标识

不提供地址输入框，不提供微信 ID 输入框，不提供登录入口。

### 响应式行为

- 桌面端使用固定宽度右侧抽屉，宽度约 420px。
- 窄屏端抽屉变为全屏面板，内容可以纵向滚动。
- 抽屉打开时禁止页面背景滚动。
- 支持键盘 `Tab`、`Shift+Tab`、`Esc` 和可见焦点状态。

## 数据模型与持久化

新增 `src/events/sourceConfig.js`，负责默认目录、名称编辑状态、名称规范化和配置 API 调用。默认目录从 `data/wechat-event-sources.json` 复用，避免在前端重复维护 37 个名称。

项目 JSON 继续使用现有结构：

```json
{
  "sources": [
    {"id": "qbitai", "name": "量子位", "category": "ai", "feedUrl": "", "enabled": false}
  ],
  "manualArticleUrls": []
}
```

前端只提交用户可编辑的 `id` 和 `name`，本地 API 以项目 JSON 中的原始记录为基底合并名称，保留 `category`、`feedUrl`、`enabled`、确认状态和其他字段，避免配置面板误删抓取设置。

本地 API：

- `GET /__events/source-config`：读取当前项目 JSON
- `PUT /__events/source-config`：校验并写入名称列表
- 仅在 Vite 开发服务器启用
- 只接受本机请求
- 采用临时文件加替换的原子写入方式
- 不接受 URL、Cookie、Token 或其他登录信息

部署到 GitHub Pages 后没有这个 API，页面进入只读提示状态；配置必须在本地开发页完成。

名称规范化规则：去除首尾空白、合并连续空格、拒绝空名称，保留中英文、数字和原始标点。重复名称不重复添加；重复时聚焦已有行并提示用户。

## 组件边界

### `SourceConfigDrawer.jsx`

负责抽屉展示、打开关闭、键盘交互、名称编辑、新增和保存按钮。它不负责活动数据抓取。

### `sourceConfig.js`

负责：

- 读取默认来源目录
- 规范化名称
- 生成搜索词预览
- 调用本地配置 API 读取和写入项目 JSON
- 管理未保存的页面编辑
- 恢复当前项目 JSON 中的默认名称
- 合并公开来源状态

### `EventsApp.jsx`

负责：

- 渲染页头入口
- 控制抽屉开关
- 将 `payload.sources` 状态传给抽屉
- 保持现有活动筛选和活动列表逻辑不变

### `events.css`

增加抽屉、遮罩、来源行、状态标记、滚动区域和移动端布局样式，继续使用现有活动雷达的颜色和字体变量。

### `vite.config.js`

增加仅开发模式启用的本地配置中间件。中间件不参与生产构建，也不出现在 GitHub Pages 静态产物中。

## 数据流

```text
data/wechat-event-sources.json
          ↓
  默认来源目录（37 条）
          ↓ 与 payload.sources 合并状态
   SourceConfigDrawer
          ↓ 用户编辑名称
       local Vite API
          ↓
 data/wechat-event-sources.json
          ↓ git commit / push
    GitHub Actions 每日读取
```

保存到项目 JSON 后，名称会成为下一次 GitHub Actions 刷新的输入；在提交和推送之前，公开站点和云端任务不会变化。当前公开活动列表仍然读取 `wechat-events.json`，不会因为页面尚未保存的编辑而伪造新的活动数据。

## 错误处理

- 本地 API 不可用时，页面继续显示来源，但保存按钮改为不可用，并显示“请在本地开发服务器中配置”。
- 项目 JSON 解析失败或写入失败时，保留页面编辑，不显示成功状态，并提示用户检查文件和终端日志。
- 名称为空时不允许保存，并在输入框附近显示明确提示。
- 同名新增不创建重复项。
- 公开活动数据请求失败时，抽屉仍然显示 37 个默认名称；来源状态显示“状态暂不可用”。
- 保存按钮在请求完成前禁用，完成后显示“已保存到项目 JSON”和保存时间。
